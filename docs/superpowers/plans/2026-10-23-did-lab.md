# DID Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Homologar os DIDs conhecidos e sua rejeição segura em Asterisk real.

**Architecture:** Estender o laboratório descartável existente com `--dids`,
um tronco TLS autenticado e observadores de ramais. Validar o resultado
SIP, mídia, CDR novo e ausência de encaminhamento cruzado.

**Tech Stack:** Python stdlib, pytest, pylibsrtp 1.0.0, Asterisk 22.11.0,
Docker e GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-did-lab-design.md`.

## Global Constraints

- Somente loopback; configurações exportadas do commit Git.
- Senhas, SDP, chaves e CDR bruto nunca são publicados.
- DIDs desconhecidos, removidos e órfãos devem ser negados antes do Answer.
- Nenhuma integração automática em main ou autorização operacional.

## Review Focus

- Resposta SIP de outra transação não pode comprovar rejeição.
- Um CDR antigo não pode comprovar a chamada atual.
- EOF ou falha do observador não pode comprovar ausência de toque.
- Remoção ou mapeamento órfão não pode entrar na URA.
- O aceite não pode passar com um cenário ausente ou valor truthy.
